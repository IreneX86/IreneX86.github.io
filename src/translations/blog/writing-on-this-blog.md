这是这个网站的第一篇正式文章。

比起用传统的“Hello, World”开场，我更想留下一份简短的排版参考，方便以后写笔记时使用。它既是介绍，也是测试页；如果忘记了某个细节应该是什么样子，我还可以回来看看。

## 文字

大多数文章都会由普通段落组成。有些只是记录一个简单的观察，有些则需要更多篇幅，把一个想法仔细讲清楚。

比起在一屏里塞进尽可能多的内容，我更在意舒适的阅读宽度。长段落也应该读起来从容：行与行、章节与章节之间留出足够空间，让技术文章容易理解，而不必把每个想法都做成独立的界面元素。

### 强调

我可以用**粗体**突出重点，用*斜体*表达较轻的语气变化，也可以在需要时使用***粗斜体***。像 `npm run dev` 这样的命令，以及 `src/data/blog/` 这样的路径，用行内代码展示会更清楚。

想了解这个网站使用的框架，可以查阅 [Astro 文档](https://docs.astro.build/)。

## 列表与结构

以后的笔记可能会包含：

- 值得保留的小发现；
- 代码片段与实验；
  - 包括简短的补充说明或注意事项；
- 有用的参考链接；
- 想在以后重新思考的问题。

日常写作流程也很简单：

1. 编写一个 Markdown 文件。
2. 使用 `npm run dev` 预览网站。
3. 使用 `npm run build` 构建，并运行 `npx astro check`。
4. 提交写好的文章。
5. 推送到 GitHub。

> 笔记不必很长。只要再次找到它时，它仍然有用就好。

## 代码

围栏代码块可以标注语言，让示例更容易阅读。下面是一个简单的 Python 函数：

```python
def greet(name: str) -> str:
    return f"Hello, {name}!"


print(greet("Irene"))
```

TypeScript 既可以展示数据的结构，也可以展示对它进行的操作：

```typescript
type Note = {
  title: string;
  published: boolean;
};

const describe = (note: Note): string =>
  `${note.title}: ${note.published ? "published" : "draft"}`;
```

简短的 Shell 代码块可以记录发布文章前的本地检查命令：

```bash
npm run dev
npm run build
npx astro check
```

介绍 `<Component />`、`{ value: true }` 或 `a > b` 这样的语法时，行内代码也很有用。设置 `draft: true` 可以让草稿暂时不出现在已发布的网站上。

## 表格与图片

小表格能让简短的对比更容易浏览。

| 格式 | 适用场景 |
| --- | --- |
| 段落 | 普通写作 |
| 列表 | 相关想法或操作步骤 |
| 引用 | 值得单独呈现的一句话 |
| 代码 | 命令与示例 |

以后可以通过普通 Markdown 语法添加图片，例如 `![替代文本](/path/to/image.png)`。图片说明可以等真正需要时再加。
